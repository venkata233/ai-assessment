## Expected failure modes
- **Check-then-insert race on unique values**: check by: Rely on a database unique constraint and handle the violation; never only check first.
- **Non-cryptographic randomness for unguessable values**: check by: Use a cryptographically secure generator (for example `secrets`).
- **String-built SQL and N+1 queries**: check by: Use bound parameters; inspect query plans for the hot paths.
- **Secret comparison with `==`, credentials in logs**: check by: Constant-time comparison; redact credentials in logs; test it.
- **Naive URL validation (prefix checks, internal addresses)**: check by: Parse properly; reject unsafe schemes and internal targets; test adversarial inputs.
